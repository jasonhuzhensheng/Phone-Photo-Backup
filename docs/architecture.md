# 架构说明

## 当前实现

项目是本地桌面工具：用户先用手机系统或其他方式将文件导出到电脑目录，再选择该目录与另一个本地备份位置。程序不直接连接 iPhone/Android，不调用云服务，不转换媒体内容。

## 模块职责与数据流

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| `src/desktop_app.py` | Tkinter 界面、目录选择、扫描预览、进度和结果反馈 | 不实现文件复制策略；后台线程执行扫描和备份 |
| `src/phone_photo_backup.py` | 路径校验、递归扫描、文件复制、SHA-256 校验、版本冲突处理、JSON 清单 | 只写用户选定的目标目录；不修改或删除来源文件 |
| `tests/test_phone_photo_backup.py` | 使用临时模拟字节测试复制、跳过、冲突、路径和符号链接行为 | 不访问私人照片 |
| `docs/` | 架构和决策记录 | 事实以已实现代码为准 |

流程：界面读取两个目录 → 引擎验证源和目标不重叠 → 扫描普通文件并预览数量/体积 → 用户确认 → 对每个文件计算 SHA-256 → 将字节流写入临时文件并校验 → 原子移动到目标 → 原子更新 `.phone-photo-backup.json`。目标以来源目录名加 `_backup` 命名，保持相对目录结构。

相同相对路径且哈希未变时跳过；若内容变化，则保留原文件并将新版本写为 `*.conflict-<hash>`。清单按相对路径追踪不同版本，不保存原始绝对路径。符号链接不会跟随或复制。

## 安全与限制

来源与实际备份目录不得相互嵌套，避免递归备份。复制使用分块读写，完成后验证哈希；失败时保留原件并清理未完成的临时文件。当前没有断点续传、撤销、恢复、加密或设备直连功能。目的盘的可靠性、容量和加密由用户负责。
